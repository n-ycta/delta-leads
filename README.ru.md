# Delta Leads

**[English](README.md) · [Русский](README.ru.md)**

Временный личный плагин поиска лидов для [Delta](https://github.com/n-ycta/delta). Ищет заказчиков RU/EN на автоматизацию, сайты и лендинги, ботов, скрипты, парсеры и API-интеграции. Плагин работает на узле без открытого браузера. Ядро менять не требуется; в Delta Web нет привязки к конкретному плагину.

## Установка

1. Обновите **Delta Web до 0.6.0 или новее** — нужен UI-контракт 1.5.
2. Откройте **Плагины → Delta Leads → Установить** и выберите узел. Каталог устанавливает релиз с проверкой SHA-256, supervisor выдаёт отдельный токен только для регистрации компонента.
3. В **Настройках** уже загружена предустановка RU/EN. По умолчанию: Reddit RSS, проверка каждые 5 минут, посты не старше 24 часов.
4. Укажите токен Telegram-бота и **chat ID получателя**, включите отправку. Сначала откройте бота и нажмите **Start**. Действие **Тест Telegram** отправляет одно проверочное сообщение.
5. При желании включите **Вердикт нейросети**: базовый URL OpenAI-совместимого API, модель, API-ключ, описание своих услуг и порог уверенности. Локальная модель: например, `http://127.0.0.1:11434/v1`.
6. Нажмите **Проверить сейчас**. Это запускает фоновую проверку, а не заставляет ждать её завершения в HTTP-запросе.
7. В обзоре доступны **Посты и вердикты**, **Счётчики за всё время**, **Доступность и охват источников**. Кнопка **Дашборд** открывает графики и счётчики. Принятые лиды также появляются в центре уведомлений Web.

Через API установка вызывается так:

```sh
delta call packages.install --json '{"id":"dev.delta.leads"}'
```

## Как определяется лид

Сначала проверяются свежесть, язык и заблокированные авторы. Затем — признаки рекламы исполнителя и исключения: предложения услуг, поиск работы, обучающие материалы, демонстрация своего проекта, советы и полная занятость. Только после этого ищутся **вместе намерение заказать и подходящая услуга**. Общее «looking for» само по себе не считается намерением купить.

Если включена нейросеть, она получает только прошедших правила кандидатов. Пост — недоверенные данные, а не инструкции для модели. Модель возвращает вердикт, уверенность и объяснение. Ответ проверяется; при ошибке кандидат остаётся `pending_ai`, при недостаточной уверенности — `uncertain`. Уведомление не отправляется. Нейросеть не может превратить отсеянного правилами конкурента в лид.

Начальные пороги: **75 баллов правил**, **0,85 уверенности ИИ**. Это осторожная предустановка, **не измеренная точность и не гарантия заказов**. Настройте её на своих примерах. Оригинальные тексты постов, поисковые фразы, названия моделей и объяснения модели не переводятся принудительно; системные подписи, настройки, ошибки и статусы доступны на RU/EN.

## Гибкая настройка

| Настройка | Назначение |
| --- | --- |
| `queries` | До 12 запросов, по одному на строку; синтаксис выбранной сети |
| `services` | Ваши услуги и тематические ключевые слова |
| `buyerTerms` | Фразы намерения заказать работу |
| `sellerTerms` | Фразы конкурентов, исполнителей и соискателей |
| `excludedTerms` | Исключающие фразы |
| `minScore` | Минимальная оценка правил |
| `languages` | Русский, английский или оба |
| `blockedAuthors` | `имя` или `источник:имя`, по одному на строку |
| `subreddits` | Сабреддиты через запятую; пусто — весь Reddit |
| `freshnessHours` | Максимальный возраст: 1–168 часов |
| `intervalSec` | Интервал проверки: от 60 секунд; проверки не перекрываются |
| `xQueries`, `threadsQueries` | Отдельные запросы X/Threads |
| `profile` | Ваши услуги и портрет заказчика для нейросети |
| `aiMinConfidence` | Порог уверенности модели |
| `maxAiPerScan`, `maxTelegramPerScan` | Лимиты стоимости и отправок за проверку |
| `notificationLocale` | Язык Telegram и inline-кнопки: RU/EN; Web следует языку консоли |
| `retentionDays` | Срок локальной истории: 1–90 дней, очистка при проверках |

**Проверить правила на тексте** — без отправки и без вызова модели. **Оценить лид** — ручные метки «Подходит», «Ложное срабатывание», «Связался», «Заказ получен». ID записи виден в таблице. Скрытого самообучения или автоматической рассылки потенциальным заказчикам нет.

## Источники и доступ

- **Reddit:** публичный RSS/Atom, публичный JSON или OAuth API. OAuth использует данные вашего приложения; при наличии refresh token — пользовательскую авторизацию, иначе client credentials. Reddit может ограничивать публичные запросы и требовать одобренный доступ к API.
- **X:** официальный API недавнего поиска. Нужен Bearer token и тариф/доступ с разрешением поиска. Это не бесплатный парсер сайта и не обещание полного архива.
- **Threads:** официальный поиск по ключевым словам. Нужен пользовательский токен с `threads_basic` и одобренным `threads_keyword_search` для поиска чужих публичных постов; без одобрения охват может быть ограничен вашими постами.

Способ доступа Reddit выбирается явно. Плагин не обходит запреты, CAPTCHA и лимиты, не собирает пароли или cookies и не переключается скрытно на другой метод после отказа авторизации. Ошибки и время повторной попытки видны в таблице источников.

Максимум три страницы на запрос; RSS ограничен размером выдачи. Неполный охват отмечается отдельно. Ни успешная проверка, ни RSS не гарантируют, что найдены все посты сети. Недоступность сообщества, права API, удалённые посты и особенности поиска влияют на результат.

Официальная документация: [Reddit](https://www.reddit.com/dev/api/), [OAuth](https://github.com/reddit-archive/reddit/wiki/OAuth2), [X](https://docs.x.com/x-api/posts/recent-search), [Threads](https://developers.facebook.com/docs/threads/keyword-search), [Telegram](https://core.telegram.org/bots/api#sendmessage).

## Уведомления и повторная доставка

Web получает принятые лиды независимо от Telegram. В Telegram отправляется заголовок, источник, автор, время, выдержка, оценка/вердикт и **inline-кнопка перехода к посту**.

Все принятые лиды попадают в сохраняемую очередь независимо от подключения Telegram. При включении отправки свежие неотправленные лиды ставятся на доставку. Временные ошибки повторяются с задержкой, просроченные лиды больше не отправляются, постоянные ошибки остаются видимыми. AI-кандидаты ожидают следующего лимита или повторной попытки с учётом свежести.

Доставка **at-least-once, не exactly-once**: если Telegram уже принял сообщение, но ответ потерялся или процесс упал до сохранения результата, повтор может создать дубль. Bot API не поддерживает пользовательский ключ идемпотентности.

## Приватность

Токены вводятся секретными полями. API не возвращает их значения — только имена уже настроенных секретов. Незаполненное поле сохраняет прежний токен; кнопка удаления явно очищает его.

`DATA_DIR/settings.json` и `state.json` записываются атомарно. На POSIX: каталог 0700, файлы 0600. На Windows используйте приватный каталог профиля и ACL своей учётной записи. Секреты нужны процессу во время работы и **хранятся локально без шифрования**, поэтому не публикуйте каталог данных и не добавляйте его в Git. Реальных ключей в коде, предустановке и тестах нет.

При включённом ИИ текст публичного поста передаётся выбранному провайдеру; при выключенном — нет. HTTPS обязателен, кроме HTTP на localhost для локальной модели. Не направляйте API-ключи недоверенному серверу.

Хранится максимум 5 000 постов, 30 000 ключей дублей и 3 000 временных корзин проверок. Общие счётчики переживают очистку; графики строятся только по сохранённой истории. Это однопроцессный личный плагин, не распределённая очередь.

## API и разработка

Компонент: `leads`, UI ID: `dev.delta.leads`. Приватные данные и управление требуют владельца/admin или явного `admin:leads.*`.

Возможности: `leads.status`, `settings`, `scan_now`, `list`, `statistics`, `sources`, `notifications`, `metrics_query`, `preview`, `feedback`, `test_telegram`. Таблицы принимают `offset/limit`, фильтры и `_locale`, возвращают `{rows,total}`. Машинные коды вердиктов стабильны; подписи выводятся отдельно. Полная таблица аргументов — в [английском README](README.md#api).

```sh
npm ci
npm test
# Для ручного запуска нужны DELTA_URL, отдельный DELTA_TOKEN и приватный DATA_DIR.
npm start
```

Node 22+, рекомендуется 24. Архитектура, ревью, альтернативы и план — в [ARCHITECTURE.md](docs/ARCHITECTURE.md); результаты проверок — в [VERIFICATION.md](docs/VERIFICATION.md).

Будущее разделение: коннекторы, парсинг и уведомления → `delta-connect`; правила, ИИ и планирование → `delta-flow`. Сейчас они изолированы модулями внутри одного рабочего плагина.

## Профили и диагностика (0.1.2)

В **Настройки → Профили** можно объединить AI-автоматизацию, сайты/лендинги, ботов/скрипты и иллюстрацию/дизайн. Нажмите **Просмотр** и отметьте поля для замены. Неотмеченные сохранят ваши значения; кастомные поля не выбираются автоматически, AI-промпт всегда защищён по умолчанию. Для сброса отдельного поля снова откройте профили и отметьте его. **Применить** меняет только форму; затем требуется **Сохранить**. Секреты и уведомления профилями не заменяются.

Кнопки **AI** и **Telegram** проверяют текущие поля без сохранения. AI выполняет один реальный запрос модели с проверкой JSON (может быть платным). Telegram проверяет бота и доступ к чату; **Отправить** отдельно проверяет доставку. Если провайдер не поддерживает response_format, отключите соответствующую настройку.

Режимы AI: последовательный, параллельные одиночные запросы (1–8), JSON-пакеты (1–10 постов). Лимит за проверку считается в HTTP-запросах, а не постах. Ошибочные, неполные или дублирующиеся ID в ответе пакета не допускаются. Общая пауза AI после лимита/ошибки авторизации сохраняется между проверками и перезапусками; замена ключа, URL или модели снимает её.

**Диагностика** берёт выборку за сутки: первый запрос и первую страницу каждого включённого источника; по желанию — одного AI-кандидата. Лиды не сохраняются, сообщения не отправляются, паузы соблюдаются. Это не полный обход всей соцсети. Фоновый поиск включается отдельно. Результаты — в таблице диагностики.

Схема VPS + компьютер поддерживается через зарегистрированные возможности ядра и явно настроенное доверие между узлами. Физическое место запуска Web не определяет узел плагина. Проверьте доступность исходящих API именно с компьютера, где работает плагин.

### Очередь, таблица и ветвления (Web 0.6.2+)

Каждый принятый лид сохраняется в очереди, даже до подключения Telegram. После включения доставки свежие неотправленные лиды, включая старые записи «отключено», попадают на отправку. Устаревшие исключаются, уже отправленные повторно не ставятся в очередь. Доставка работает отдельно от поиска; Retry-After приостанавливает всю очередь. При смене параметров подключения можно повторить доставку после ошибки авторизации. Гарантия at-least-once: при неоднозначном сетевом сбое возможен дубль.

На дашборде — существующий виджет таблицы с кликабельными названиями постов, вердиктом, причиной AI и состоянием Telegram, новые сверху. В последовательном режиме скрыты параллельность и размер пакета; в остальных видны только актуальные поля. Скрытые значения сохраняются.
