# Reliability and UI review

Tested in an isolated two-node Linux environment, not on a user production installation.

- Web: responsive route audit at 390/768/1440 pixels in Russian and English, plus typed clickable table links, conditional fields and generated/user dashboard classification. Shared components were fixed rather than adding plugin-specific Web code.
- Remote core: actual official 0.4.0 to 0.4.1 replacement on a paired node, same node identity after restart, target-side worker survival, health verification and cleanup. Owner trust is mandatory; scoped call access is insufficient. Official user-managed core installation and a usable Node.js runtime are required on the target. Windows branches are unit/source checked, not end-to-end tested on Windows.
- Telegram: HTML escaping, paragraphs, timezone validation, maximum-size Unicode posts, Retry-After JSON and queue isolation for a malformed row. Tests mock Telegram; no unsolicited production messages are sent.
- Classification: explicit regression for an unrelated virtual-assistant vacancy mentioning software services only in its company description. Rules remain heuristic; AI provider behaviour and live social-network rate limits cannot be guaranteed.

Automatic remote core updates are off by default and require explicit separate consent. Transient network ambiguity leaves the target worker running rather than terminating an update in progress. Telegram delivery remains at-least-once.
